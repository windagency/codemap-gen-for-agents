# High-level design

[Back to README.md](../README.md) • [Back to 0029-json-envelope-warnings-field.md](adr/0029-json-envelope-warnings-field.md) • [Back to FLOWS.md](FLOWS.md) • [Back to LLD.md](LLD.md) • [Back to NEXT_STEPS.md](../NEXT_STEPS.md)

A four-stage pipeline behind three peer integration adapters, wired once at a single composition root. This document is the architectural "why" and "shape"; for exact interfaces and types see [`LLD.md`](LLD.md), and for the decision history behind each choice see [`documentation/adr/`](adr).

## Design goals

- **Deterministic and reproducible.** The same input code produces the same `codemap.json` on every run - golden-file and repeatability tests depend on this. No LLM call, no non-deterministic ordering, anywhere in the pipeline.
- **Type-checked where it's proven out, syntactic where it isn't yet.** TS/JS extraction uses the TypeScript Compiler API's real type checker ([ADR-0002](adr/0002-ts-compiler-api-over-tree-sitter.md)); Go/Rust/Java/Python extraction uses tree-sitter, syntactic (repo-wide name-based candidate matching) rather than type-checked ([ADR-0027](adr/0027-tree-sitter-multi-language-extraction.md), [ADR-0030](adr/0030-tree-sitter-python-support.md)) - a deliberate, documented fidelity split, not an oversight.
- **No human declaration for Module boundaries.** Domain grouping is computed by graph community detection over the combined, whole-repo static import graph - every language's files in one run, never clustered per-language in isolation - with no config file or LLM guess ([ADR-0001](adr/0001-algorithmic-module-detection.md)).
- **Offline-capable output.** `codemap.html` is a single self-contained file; nothing it needs is fetched at view time.
- **Incremental where it's cheap, global where it must be.** Extraction skips unchanged files; module clustering always recomputes globally, since boundaries can shift without any single file changing ([ADR-0005](adr/0005-incremental-extraction-caching.md)).
- **Multi-language by seam, not by special-casing.** The `Parser` seam already carries five registered implementations (TS/JS, Go, Rust, Java, Python, [ADR-0003](adr/0003-generator-pipeline-seams.md)); a `CompositeParser` partitions the file set by extension and merges each language's own output before `GraphBuilder` ever sees it, which itself stays completely language-agnostic.

## Seams

Five extension points, each independently replaceable, per [ADR-0003](adr/0003-generator-pipeline-seams.md):

| Seam               | Selection                                                                                        | Why a seam                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Discovery**      | Direct injection, single implementation                                                          | The one piece of structural info (Package/Directory boundaries) that comes from the filesystem, not from parsed file content - a genuinely separate concern from everything downstream.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Parser**         | Factory (`ParserFactory.createParser(language)`), wrapped by a `CompositeParser` at `compose.ts` | Five registered implementations (TS/JS, Go, Rust, Java, Python); a future language registers its own without touching the pipeline shape. `CompositeParser` partitions Discovery's file lists by extension and merges each language's `ExtractedSymbols[]` before `GraphBuilder` ever sees them ([ADR-0027](adr/0027-tree-sitter-multi-language-extraction.md), [ADR-0030](adr/0030-tree-sitter-python-support.md)). Each per-language implementation is whole-program by design - TS/JS's type checker only resolves cross-file calls correctly when its entire file set loads into one `ts.Program`; Go/Rust/Java/Python's repo-wide candidate matching needs the same whole-language-program view to find every same-named declaration. |
| **GraphBuilder**   | Factory, single implementation registered                                                        | Its eventual selection axis isn't assumed to track language, so it's kept as its own registered seam rather than bundled with Parser. Deliberately a pure function of already-resolved data - no filesystem or type-checker access.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **ModuleDetector** | Direct injection, single implementation                                                          | Wraps the third-party `graphology-communities-louvain` library behind a domain-named interface, satisfying this repo's library-isolation rule (`CODING_RULES/04-architecture.md`). Never called an "Adapter" - that word is reserved for the tool-integration sense below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Transformer**    | One interface, two implementations (JSON, HTML)                                                  | `transform(graph, options?)` covers both output formats; `options` leaves room for output-specific parameters without renegotiating the interface.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## Adapters

Three tool-integration surfaces, all peers of `core/compose.ts`'s `createDefaultPipeline()` - none delegates to another:

- **CliAdapter** - one-shot `generate` from a terminal or script.
- **McpAdapter** - `generate`/`read` tools for any MCP client. `read` self-heals by re-running the pipeline before filtering.
- **SkillAdapter** - a companion script a Claude Code Skill invokes directly, exposing both `generate` and `read`. It calls core directly, the same way the CLI and MCP server do, rather than shelling out to either of them.

This "Adapter" is reserved specifically for these three tool-integration seams - a different concern from `ModuleDetector`'s third-party-library isolation, even though both are informally "wrapping something." See [ADR-0003](adr/0003-generator-pipeline-seams.md)'s Context for why the two needed distinct names.

## Incremental caching

Extraction is the only incremental stage. `Parser.parse(programFiles, extractFiles)` splits "files the type checker needs loaded" (always the complete current set, for correct cross-file resolution) from "files actually walked for symbols" (the content-hash-changed subset). `GraphBuilder` and `ModuleDetector` always run over the complete, current `ExtractedSymbols[]` - fresh entries for changed files, cached entries for the rest - so module clustering is never itself incremental. See [ADR-0005](adr/0005-incremental-extraction-caching.md) and [`FLOWS.md`](FLOWS.md#generate-incremental-re-run) for the exact decision sequence.
