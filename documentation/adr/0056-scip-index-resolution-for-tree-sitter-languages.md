# 0056: Go/Rust/Java/Python resolution comes from a SCIP index, tree-sitter stays the fallback

[Back to documentation/adr/README.md](README.md) • [Back to NEXT_STEPS.md](../../NEXT_STEPS.md)

## Status

Accepted. Scopes the toolchain-based resolution item in `NEXT_STEPS.md`. Nothing is implemented yet; each language lands as its own slice, per decision 7.

## Context

[ADR-0027](0027-tree-sitter-multi-language-extraction.md) put Go, Rust, and Java on tree-sitter at a deliberately lower fidelity than TS/JS. [ADR-0030](0030-tree-sitter-python-support.md) put Python on the same tier. An unqualified call there yields every same-named top-level declaration as a candidate. A qualified call can still misresolve when a syntactic heuristic guesses wrong. ADR-0027 reserved a toolchain-based upgrade and recorded its cost: the target repo's own build tooling must be installed and runnable.

`NEXT_STEPS.md` already ruled out a live LSP client. LSP is asynchronous, and `Parser.parse()` is synchronous by design. ADR-0027 rejected `web-tree-sitter` for the same reason. It pointed at SCIP instead: an indexer runs out of process, then its output file is read synchronously.

The facts this ADR builds on, checked on 2026-10-09:

- SCIP is a Protobuf format. Its home moved from `sourcegraph/scip` to `scip-code/scip`.
- The TypeScript binding is `@scip-code/scip` 0.10.0. It is ESM-only, Apache-2.0, and generated by `protoc-gen-es`. Its one runtime dependency is `@bufbuild/protobuf`. This repo is already `"type": "module"`.
- A SCIP `Document` has an optional `text` field holding the source it was indexed from.
- Indexers per language, with their verified invocation:
  - Python: `scip-python`, at `sourcegraph/scip-python`, npm `@sourcegraph/scip-python` 0.6.6. Built on Pyright. `scip-python index . --output <path>`, default output `index.scip`. It calls `pip` to read the active environment's packages.
  - Go: `scip-go`, at `scip-code/scip-go`. Installed with `go install`. `scip-go --output <path>`, default output `index.scip`. Needs a Go toolchain and a resolvable module graph.
  - Rust: rust-analyzer's own `rust-analyzer scip <path> --output <path>`, default output `index.scip`. Needs Cargo and a loadable workspace.
  - Java: `scip-java index`, at `scip-code/scip-java`. Writes `index.scip` in the working directory. It drives the project's own build: for Maven, `clean verify -DskipTests` by default. Needs a JDK plus Maven, Gradle, or sbt. An output-path flag was not confirmed.
- `NEXT_STEPS.md` named `lsif-java` for Java. That name is stale; `scip-java` replaced it.
- Nothing in `src/` spawns a subprocess today.

## Decision

### 1. The generator reads a supplied index by default, and runs indexers only when asked

Reading a supplied `.scip` file is the default path. It never executes the target repo's code.

An opt-in switch makes the generator run the indexers itself:

- CLI and Skill: `--run-indexers`. The Skill gets it through the shared `generateFromArgv`.
- MCP `generate`: `runIndexers?: boolean`.
- MCP `read` never runs indexers. Its self-healing `generate` call hardcodes `runIndexers: false`, the same way it hardcodes `force: false`.

With the switch on, for each language that has files to extract and no supplied index:

- One indexer run per Package root of that language, with that root as the working directory.
- Spawned with `spawnSync`, so `Parser.parse()` stays synchronous. A fixed argv per language, never through a shell. The child inherits the generator's environment, so an activated Python virtualenv is what `scip-python` sees.
- Output goes to `<outDir>/scip/<packageId>.scip`, never into the target repo. Java writes `index.scip` in its working directory, so the generator moves it out afterwards. A pre-existing `index.scip` there is never overwritten or deleted.
- Each run has a timeout, 600 seconds by default, configurable as `indexerTimeoutSeconds`.
- A missing binary, a non-zero exit, or a timeout is never fatal. That Package falls back to tree-sitter and gets one warning naming the indexer and the reason.
- An index is regenerated only when a file of its language under its Package root changed by content hash, or when the index is missing. An unchanged Package reuses its earlier index.
- Each indexer run logs start, exit status, and duration through the logging adapter ([ADR-0022](0022-structured-logging-adapter.md)).

The safety cost is real and is the reason the switch is off by default. Running an indexer runs the target repo's build. `scip-java` runs Maven or Gradle with the project's own plugins. rust-analyzer runs build scripts and procedural macros. `scip-python` calls `pip`. Turning the switch on means trusting the target repo the same way building it would. The CLI help, the MCP tool description, and `USER_GUIDE.md` all have to say so.

Process spawning lives behind an `adapters/` module, so tests substitute a fake runner and never need a toolchain installed.

### 2. Index paths come from arguments, config, or a default, in that order

A supplied index path can come from three places. The first one that names a language wins for that language:

1. CLI and Skill: `--scip-index <language>=<path>`, repeatable. MCP `generate` and `read`: `scipIndexes?: Record<language, string>`.
2. Config file: a `scipIndexes` key of the same shape.
3. Default: `<rootDir>/index.scip`. A document in it is used only when its SCIP `language` field matches.

Paths are relative to the repo root. `<language>` is one of `python`, `go`, `rust`, `java`. Any other value is rejected. The CLI parse, the MCP input schema, and the config schema all validate with Zod, under [ADR-0004](0004-public-interface-contract.md)'s rules for public-interface changes.

A supplied index always takes precedence over `--run-indexers` for its language. The generator never re-indexes over an index the operator provided.

### 3. A SCIP-backed parser wraps the tree-sitter parser, never replaces it

For each of `python`, `go`, `rust`, `java`, `parser-factory.ts` registers a parser that does this:

- Symbols still come from tree-sitter. Symbol ids, kinds, line ranges, and `isTestItem` stay byte-identical with or without an index. Module detection and every existing snapshot are unaffected by symbol extraction.
- At each call or import site where the index has a reference occurrence, the index wins. A reference to a symbol defined in this repo becomes one `RawCallCandidate`, not a candidate list. A reference to a symbol from another package becomes an `external` target, using the SCIP `Package` manager, name, and version.
- At a site with no SCIP occurrence, tree-sitter's candidates stay. An indexer that skips a construct never removes an edge tree-sitter found.
- A file the index does not cover, or covers stale per decision 4, falls back to tree-sitter entirely.

This needs no change to the `Parser` interface or `ExtractedSymbols`. It is a mapping problem: a SCIP definition range has to match a tree-sitter `RawSymbol` by file and line. A SCIP definition with no matching `RawSymbol` is dropped, the same posture as an unresolved import today.

### 4. Staleness is checked per document by content, never by modification time

Modification time was rejected. A git checkout, a clone, or a CI cache restore resets it, so it gives false results both ways.

Each indexed document is checked by the strongest test available to it, in this order:

1. The document carries `text`: the current file content must equal it exactly.
2. The generator produced the index under decision 1: it also wrote `<outDir>/scip/<packageId>.hashes.json` with each file's content hash at index time. The current hash must match.
3. Neither: anchor check. Every definition occurrence must still land on an identifier whose text equals the SCIP symbol's last descriptor name. Every reference occurrence the parser would use must do the same. One mismatch marks the whole document stale.

A stale document falls back to tree-sitter. Each fallback is reported once in the `warnings` field ([ADR-0029](0029-json-envelope-warnings-field.md)), as `index stale` or `index missing`, with the file path. It is never a silent guess.

The anchor check has one known gap. An edit that adds a call without shifting any existing occurrence passes it. Decision 3 covers that gap: the new call site has no SCIP occurrence, so tree-sitter resolves it.

An aliased import makes a reference's text differ from its descriptor name, so the anchor check flags it as stale. That fallback is conservative and safe. It costs fidelity, not correctness.

### 5. Index content joins the cache epoch

[ADR-0005](0005-incremental-extraction-caching.md)'s epoch already hashes dependency manifests. The content hash of every index used this run joins it, whether supplied or generated. A changed index forces a full re-extraction. That is coarse, but it matches ADR-0005's own tradeoff: a missed invalidation produces a wrong map, not a slow one.

### 6. The Protobuf binding lives behind an adapter

Required by `CONTRIBUTING.md`'s non-negotiables. `@scip-code/scip` and `@bufbuild/protobuf` are imported only from one `adapters/` module. That module decodes the file and hands back a plain, Zod-validated shape: documents, occurrences, symbol roles, and external package identities. Nothing else in `src/` sees a Protobuf message type. The dependency-direction test gains a matching rule for this adapter and for the process-spawning one.

### 7. Rollout is one language at a time, Python first

Order: Python, then Go, then Rust, then Java.

Python first has one specific caveat. `scip-python` resolves third-party imports only through the environment's installed packages. Without an activated environment, in-repo references still resolve from the index. Third-party references keep [ADR-0030](0030-tree-sitter-python-support.md)'s PEP 503 name matching. That also recovers the irregular cases ADR-0030 leaves unresolved, such as `PIL` to `Pillow`, whenever the environment is present.

Each language ships with its own fixture repo and a committed `.scip` file, so tests never need the toolchain installed. Each language gets its own update section here for its fidelity caveats, the same way ADR-0030 recorded Python's.

## Consequences

- An indexed call site resolves to a single type-checked target. The ADR-0027 candidate-list caveat no longer applies to it. An unindexed site keeps that caveat unchanged.
- The same repo can now produce different maps depending on whether an index was supplied or generated. The `warnings` field is what tells a reader which files took which path.
- With `--run-indexers` off, the generator still needs no Go, Cargo, JDK, or Python install. The toolchain constraint ADR-0027 avoided lands on whoever produces the index.
- With `--run-indexers` on, the generator executes the target repo's build tooling. That is the first time this generator runs anything from the target repo.
- The first subprocess in `src/`. Its failures are always downgraded to warnings, never to a failed run.
- `codemap.json`'s public shape is unchanged. `cache.json` and `<outDir>/scip/` gain bookkeeping files that are not part of the public contract.
- Two new production dependencies: `@scip-code/scip` and `@bufbuild/protobuf`. Both are Apache-2.0. The third-party license manifest needs regenerating with `pnpm run licenses:generate`.
- A large index is decoded fully into memory. The SCIP schema recommends streaming consumption for large indexes. Streaming is deferred until a real repo shows the need.
- The SCIP project moved organizations during 2026. Repo and package names here were correct on 2026-10-09 and should be re-checked before each language's implementation starts.

## Still open

- `scip-java`'s output-path flag. Decision 1's move-afterwards approach works without it. Confirm before the Java slice.
- The 600-second default timeout is a starting value, not a measured one. Revisit after the Python slice runs against a real repo.
